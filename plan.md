# Adrobot Campaign Console — план реализации

## Объём

Adrobot — операторская панель для ручного тестирования интеграции с Keitaro. Приложение на FastAPI + SQLAlchemy предоставляет две рабочие зоны: создание кампании и редактирование офферов существующей кампании. Все операции с Keitaro выполняются через backend, чтобы API-ключ не попадал в браузер.

## Реализация

- **Backend:** FastAPI, Pydantic, SQLAlchemy 2.x, Alembic, HTTPX.
- **Хранилище:** SQLite по умолчанию для быстрого локального запуска; PostgreSQL/MySQL-совместимый `DATABASE_URL` для развёртывания. В БД хранятся настройки интеграции и журнал операций, но не секрет API-ключа.
- **Интеграция Keitaro:** адаптер `KeitaroClient` с базовым URL, bearer/API-key авторизацией и отдельными методами для каталогов, кампаний, потоков и офферов. Форматы ответов нормализуются backend-ом, ошибки API преобразуются в понятные сообщения.
- **API приложения:** `/api/config`, `/api/catalog`, `/api/campaigns`, `/api/campaigns/create`, `/api/campaigns/{id}/offers`, `/api/operations` и `/health`.
- **Frontend:** статические HTML/CSS/vanilla JS без отдельного Node toolchain. Интерфейс разделён на «Создать кампанию» и «Редактор кампании», показывает реальные списки и числовые показатели, имеет состояния загрузки, ошибки и успешные операции.
- **Безопасность:** `KEITARO_API_KEY`, `KEITARO_BASE_URL` и `DATABASE_URL` только через `.env`; API-ключ никогда не возвращается frontend-у и не попадает в README или Git.
- **Документация:** README с миграциями Alembic, переменными окружения, запуском, тестовыми curl-запросами и пояснением структуры.

## Дизайн

### Рассмотренные направления

1. **Технический терминал** — плотная операторская консоль с моноширинными акцентами и холодным контрастом. Вероятность 0.07.
2. **Светлая лаборатория** — воздушная светлая панель с тонкими границами и синими акцентами. Вероятность 0.06.
3. **Сигнальная автоматика** — тёмная индустриальная панель с графитовыми поверхностями и янтарными сигналами. Вероятность 0.87. **Выбрано.**

### Сигнальная автоматика

- **Движение:** industrial control room / SCADA dashboard.
- **Принципы:** высокий контраст, операция видна сразу, цифры читаются как приборы, опасные действия требуют явного сигнала.
- **Цвет:** graphite `#18181B` и charcoal `#232326` создают спокойный фон; amber `#F59E0B` отмечает активные действия и внимание; green/rose показывают результат без двусмысленности.
- **Макет:** широкая рабочая область с узкой статусной rail-секцией слева и двумя вертикальными рабочими модулями вместо центрированной маркетинговой сетки.
- **Фирменные элементы:** янтарная линия состояния, моноширинные числовые чипы, маркировки `SYS / FLOW / OP`.
- **Взаимодействие:** каждое действие сразу сообщает «что отправлено», «что вернулось» и «что изменилось»; селекты и кнопки не скрывают состояние.
- **Анимация:** короткие 150–220ms переходы, мягкий pulse только у live-статуса и spinner на сетевых операциях; без декоративного motion.
- **Типографика:** Roboto Condensed для заголовков и IBM Plex Mono для ID, числовых значений и endpoint-подписей.
- **Суть бренда:** панель, которая превращает настройку Keitaro в контролируемую последовательность операций; точная, промышленная, прозрачная.
- **Голос:** короткие операционные подписи: «Поток собран. Проверьте redirect.» и «Операция завершена без локальных расхождений.»
- **Wordmark:** `ADROBOT` с янтарной вертикальной засечкой между `AD` и `ROBOT`.
- **Фирменный цвет:** safety amber `#F59E0B`.

## Критические решения

- По умолчанию приложение запускается без доступов к Keitaro в demo mode с явным статусом `not configured`; реальные операции требуют `KEITARO_API_KEY`.
- Канонический backend-маршрут создания кампании сначала создаёт сущности кампании и потоки, затем сохраняет журнал операции. При частичном сбое ответ сообщает этап и не скрывает upstream error.
- Удаление оффера выполняется только после явного клика и передаёт в Keitaro конкретный offer ID; UI обновляет данные после ответа API.
